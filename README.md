# VPN Checker

Агрегатор, тестер и раздатчик прокси с распределённой проверкой: **панель** собирает источники и формирует рейтинги, **ноды** проверяют прокси из своих сетей (проводной канал, LTE, другие страны) и присылают результаты.

Протоколы: VLESS, VMess, Trojan, Shadowsocks (SIP002, плагины obfs / v2ray-plugin), Hysteria2 (включая port hopping), Hysteria v1, TUIC, AnyTLS, SOCKS5. Транспорты: tcp/raw (+HTTP-обфускация), ws (+early data), grpc, httpupgrade, h2, quic, xhttp/splithttp, mKCP. Форматы подписок: список ссылок, base64, Clash/Mihomo YAML.

## Как это устроено

**Группа рейтинга — самостоятельный конвейер.** У каждой группы:

- свои **источники** (галочки из общего каталога на странице Subscriptions; при создании отмечены все);
- своё **расписание** опроса источников;
- свои **Proxy Retention**, **Ban Management**, **Worker Test Parameters** и фильтр протоколов;
- свои **ноды** и свой **вебхук**.

Группы изолированы: одна нода в двух группах с разными источниками даёт два независимых набора результатов, и вебхуки отдают разное. Нода без группы простаивает.

Цикл группы:

1. По расписанию (или кнопкой «Опросить сейчас») скачиваются источники группы. Источник, нужный нескольким группам, качается один раз за цикл. Если загрузка не удалась, используется последний успешный снимок, и пул из-за сбойного зеркала не пустеет.
2. Строится пул группы: дедупликация без учёта `#remark`, фильтр протоколов, пропуск «мёртвых» источников. Пул обновляется по разнице, начинается новое **поколение**.
3. Ноды группы получают задание, проверяют пул по чанкам и после каждого чанка отправляют результаты.
4. Рейтинг считается по онлайн-нодам группы и отдаётся на `/<webhook_path>`.

**Баны и retention — по паре (группа, нода).** Успех — есть пинг и пройден хотя бы один тестовый URL. После N неудач подряд прокси банится только для этой ноды в этой группе. Прокси, прошедший на ноде, остаётся у неё в проверке ещё N опросов после исчезновения из источников.

**Автоотключение источников — по паре (группа, источник).** Если за 5 последних прогонов группы у источника не было ни одного живого прокси, его прокси в группе не тестируются. Опрос источника продолжается, и тесты возобновляются, когда меняется набор конфигов. Выборка пишется, только если ноды группы действительно завершили прошлый прогон.

**Возобновление.** Панель помнит, что нода уже проверила в текущем поколении. После рестарта ноды или панели проверка продолжается с того же места, поколение и время опроса хранятся в БД.

## Панель

```bash
git clone https://github.com/GoGoButters/VLESS-Checker.git && cd VLESS-Checker
echo "PANEL_PORT=8010" > .env        # необязательно: порт и лимит памяти
echo "PANEL_MEM=768m" >> .env
docker compose up -d --build
```

Первый вход — пароль `admin`, смените его в Settings. При первом запуске создаются набор источников, тестовые URL и группа `default`.

| Переменная | Назначение |
|---|---|
| `PANEL_PORT`, `PANEL_MEM` | порт на хосте и лимит памяти контейнера (`.env`) |
| `VPN_CHECKER_SECRET_KEY` | ключ подписи cookie; если не задан, генерируется в `data/secret_key` |
| `VPN_DB_PATH` | путь к SQLite (по умолчанию `data/vpn_checker.db`) |

Страницы:

- **Ratings** — группы: источники, расписание, политики, ноды, вебхук, просмотр рейтинга.
- **Subscriptions** — общий каталог источников; видно, какие группы используют источник и где он на паузе.
- **Nodes** — прогресс каждой ноды по каждой её группе; «Перепроверить» запускает повторную проверку без опроса источников.
- **Settings** — пароль, токен нод, уровень логов нод, MCP-токены.
- **Test URLs** — общие для всех групп.

MCP: `/mcp/read/sse` и `/mcp/admin/sse`, Bearer-токены из Settings. Инструменты: группы (`get_rating_groups`, `update_rating_group`, `set_group_sources`, `fetch_group`, `get_group_rating`), источники, ноды, тестовые URL, логи.

### Обновление с версии до групп

При первом старте новой версии база мигрирует автоматически:

- создаётся резервная копия `data/vpn_checker.db.pre-v2`;
- каждая группа получает текущие глобальные настройки, все источники, текущий пул, результаты и баны своих нод;
- исключённые страны — «Украина» (раньше это было зашито в код);
- старые таблицы удаляются, файл сжимается (VACUUM).

Миграция занимает до минуты, ноды в это время повторяют запросы. Ноды старой версии продолжают работать через слой совместимости (проверяют первую группу), на странице Nodes они помечены `legacy`. Их стоит обновить.

## Нода

```bash
git clone https://github.com/GoGoButters/VLESS-Checker.git && cd VLESS-Checker/node
cp .env.example .env && nano .env    # MASTER_URL, NODE_TOKEN (Settings), NODE_NAME
docker compose up -d --build
```

Затем добавьте ноду в группу на странице Ratings. Без Docker: `node/setup.sh` (sing-box, Xray, venv), затем `node/run.sh`.

Ядра: **sing-box 1.14.4** проверяет большинство ссылок, **Xray-core 26.11.9** — то, что умеет только он (xhttp/splithttp, mKCP, HTTP-обфускация tcp, VLESS encryption). Xray 26 больше не принимает `allowInsecure`. Для таких ссылок нода перед проверкой получает сертификат сервера и закрепляет его отпечаток (`pinnedPeerCertSha256`), что эквивалентно «принять любой сертификат». Старые mKCP-серверы проверяются через FinalMask `mkcp-legacy`. VLESS и Trojan без TLS на транспортах, которые есть только в Xray, Xray 26 запрещает, и такие ссылки не проверяются.

Переменные `node/.env`:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MASTER_URL`, `NODE_TOKEN`, `NODE_NAME`, `NODE_REGION` | — | подключение к панели |
| `BIND_INTERFACE` | системный маршрут | интерфейс для трафика проверок (например, LTE-модем); через него идут и TCP-пинг, и получение сертификата |
| `CONCURRENT_CHECKS_OVERRIDE` | — | потолок параллельных проверок (каждая — отдельный процесс ядра) |
| `ENGINE_MEM_MB`, `WORKER_RESERVE_MB` | 14, 220 | нода сама ограничивает параллельность лимитом памяти контейнера: (лимит − резерв) / МБ на ядро; при 768 МБ это 39 |
| `PROXY_TIME_BUDGET_S` | 30 | бюджет на тестовые URL одного прокси |
| `TCP_PING_TIMEOUT_S`, `PING_THRESHOLD_MS_OVERRIDE`, `TCP_PING_GATE` | 3, —, 1 | TCP-пинг: таймаут, порог, отсев по пингу (0 — решает тест через туннель) |
| `ENGINE_START_WAIT_S` | 4 | ожидание старта ядра |
| `SPEED_TEST_PARALLEL` | 4 | параллельных замеров скорости |
| `TEST_URL_RETRIES`, `MAX_CONSECUTIVE_FAILURES` | 2, 3 | повторы URL и досрочный выход |
| `NODE_CONTAINER_NAME`, `NODE_MEM` | checker-node, 768m | имя контейнера и лимит памяти (docker compose) |

После рестарта нода регистрируется снова примерно через 45 секунд: столько панель держит имя за прежним экземпляром, защищая от двойников.

Каждая проверка ограничена жёстким дедлайном, а тело ответа читается не дальше `min_body_bytes`. Прокси, который «капает» данными, не может занять слот навсегда. Для протоколов поверх UDP (Hysteria, TUIC, mKCP, QUIC) TCP-пинг не применяется: пинг — время первого ответа через туннель.

## Разработка

```bash
just test     # pytest: матрица конфигов ядер, проверки через реальные серверы, сквозные тесты панели и ноды
just check    # синтаксис
```

Для тестов с ядрами нужны `SINGBOX_PATH` / `XRAY_PATH` (без них такие тесты пропускаются) и `openssl`.

Модули панели: `main.py` (UI), `node_api.py` (API нод), `pipeline.py` (расписание, пулы, чистка), `sources.py` (загрузка и разбор источников), `rating.py` (рейтинг и вебхуки, с кэшем), `database.py` / `migrations.py` (схема). Модули проверки (общие с нодой): `proxy_parsers.py`, `engine_driver.py`, `tester.py`, `speed_tester.py`, `geo_checker.py`.
